# dev 후속 개발 요구사항

## 스프레드시트 유형 분리

다음 기능 개발에서는 스프레드시트를 하나의 고정 양식으로 취급하지 않는다. 사용자가 수업을 준비할 때 아래 두 유형을 별도로 선택할 수 있어야 한다.

1. `기본수업` 스프레드시트
2. `모의고사` 스프레드시트

유형 선택은 파일을 생성하거나 붙여넣은 데이터를 읽기 전에 명확히 이루어져야 하며, 현재 선택한 유형을 화면에서 계속 확인할 수 있어야 한다.

## Preset 분류와 변수 계약

- 각 Preset에는 사용할 수 있는 스프레드시트 유형을 명시한다.
- `기본수업`과 `모의고사` Preset을 구분하여 표시하거나, 현재 스프레드시트 유형과 호환되는 Preset만 선택할 수 있게 한다.
- 스프레드시트 유형과 Preset 유형이 맞지 않으면 묵시적으로 값을 추측하지 말고 발송 전에 오류로 차단한다.
- 읽어야 하는 열과 변수는 스프레드시트 유형 및 선택한 Preset의 변수 계약에서 결정한다. 모든 Preset에 동일한 변수 집합을 강제하지 않는다.
- Preset이 실제로 사용하는 변수만 필수값으로 검증하고, 사용하지 않는 변수는 빈 값이어도 오류로 처리하지 않는다.
- Preset 편집·가져오기·내보내기 시에도 스프레드시트 유형 정보와 변수 계약이 보존되어야 한다.

## 예상 변수 범위

`기본수업`은 진도, 숙제, 시험 범위, 공지, 출결, 숙제·테스트 점수 및 코멘트처럼 일반 수업 공지에 필요한 값을 중심으로 한다.

`모의고사`는 회차별 시험명, 점수, 만점, 평균, 최고점, 등수, 응시 인원, 코멘트 및 모의고사 개수처럼 모의고사 공지에 필요한 값을 중심으로 한다.

위 목록은 초기 분류 기준이다. 구현 시에는 Template 변수 카탈로그와 Preset별 실제 사용 변수를 단일 기준으로 삼아 파서, 미리보기, 검증 및 발송이 같은 계약을 사용해야 한다.

## 호환성과 테스트

- 기존 저장 데이터와 기존 `기본수업` 흐름은 마이그레이션 후에도 그대로 동작해야 한다.
- 유형별 스프레드시트 생성, 붙여넣기 파싱, Preset 필터링, 필수 변수 검증, 미리보기 및 최종 발송까지 각각 자체 테스트를 추가한다.
- 잘못된 유형의 데이터를 붙여넣거나 호환되지 않는 Preset을 선택한 경우 안전하게 차단되는 테스트를 포함한다.
