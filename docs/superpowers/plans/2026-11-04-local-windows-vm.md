# Local Windows VM validation plan

**Goal:** Run the Windows application's remaining functional tests in a dedicated Windows VM on this PC while retaining host protection.

**Authorization:** User approved creating the local VM after the host's automation DLL was blocked. Existing exact-window automation, no-send dry-run, bot-only real-delivery restrictions remain binding. Design questions were previously waived. No host SAC, Defender, VBS, Secure Boot or trust-policy reduction. SignPath review remains independent.

**Chosen environment:** Official Oracle VirtualBox 7.2.22 Windows package with only the main application feature; use the existing Windows hypervisor capability. A separate Windows 11 Enterprise evaluation guest from Microsoft's official download, subject to its evaluation terms. Start with 4 vCPUs, 8 GiB RAM, an 80 GiB dynamically allocated disk, UEFI/TPM 2.0 and NAT. No inbound forwarding, bridged network drivers, USB passthrough or host-wide folder sharing. VM files under `%USERPROFILE%\NoticeSender-VM` to avoid syncing large disks to OneDrive or storing the VM in the Codex package cache.

## Steps

- [x] Download official host installer, match official SHA-256 and verify Oracle Authenticode publisher.
- [x] Install VirtualBox main application with no automatic restart; allow required Windows elevation through its normal prompt. Verify installed version and driver readiness. Stop if it requires weakening host protection.
- [x] Download and inspect official Korean Windows 11 Enterprise evaluation media. Record hash, edition and evaluation/licensing requirements.
- [x] Create a dedicated VM, install the guest normally and verify its desktop. Complete any required user agreements/account steps at their actual point of use.
- [x] Transfer only the application build, synthetic tests and necessary tools into the guest. No student DB or private chat exports.
- [x] Run Core/Automation/unit and isolated WPF/published-app tests inside the guest; keep actual KakaoTalk sends disabled until the test account is logged in and chatbot identity is verified.
- [ ] Install official KakaoTalk in the guest, obtain user login, and run app-owned dry-run followed by the previously authorized seven-case bot-only text/file suite. Preserve uncertain-send protection and stop at unexpected results.
- [ ] Preserve private reports and screenshots, document exact guest/host coverage and outstanding failures, commit/push appropriate source fixes on `codex/windows-port`.
