# 공지발송 for macOS

학생 DB와 Google Sheets의 수업 공지를 검증한 뒤 KakaoTalk Mac에서 정확한 방 제목을 확인하고 순차 발송하는 SwiftUI 앱입니다.

2.0부터 KakaoTalk 접근성 탐색은 [`channprj/kmsg`](https://github.com/channprj/kmsg)의 소스를 앱 내부 라이브러리로 포함해 사용합니다. 업스트림 `1.260705.0`의 `fb70208286a1da3a404861dc944db470176155f6` 커밋에 고정했으며, 학생 공지 발송에 맞게 부분 일치와 강제 타이핑을 차단했습니다. 별도 보조 프로세스가 아니므로 손쉬운 사용 권한은 `공지발송.app` 하나에만 부여합니다. MIT 라이선스와 고정 커밋 정보는 앱 번들의 `Contents/Resources/ThirdPartyLicenses`에도 포함됩니다.

## 지원 환경

- macOS 14 이상
- Apple Silicon Mac(`arm64`)
- Mac용 KakaoTalk 설치 및 로그인
- 카카오톡 채팅방 목록과 정확한 방 이름을 읽기 위한 macOS 손쉬운 사용 권한
- Google Sheets는 웹 브라우저에서 사용합니다. 앱이 Google 계정이나 Sheet API에 로그인하지 않고 복사한 셀 값만 받습니다.

## 일반 사용자 설치

1. [최신 GitHub Release](https://github.com/SleepingDawn/notice-sender-mac/releases/latest)에서 `NoticeSender-버전-macOS-arm64.zip`을 다운로드합니다. 공개 저장소이므로 GitHub 계정은 필요하지 않습니다.
2. ZIP을 열고 `공지발송.app`을 Finder의 `응용 프로그램` 폴더로 옮깁니다. 다운로드 폴더에서 직접 실행하지 마세요.
3. `공지발송.app`을 한 번 실행합니다. 현재 배포본은 Apple 공증 전 로컬 서명 빌드이므로 macOS가 개발자를 확인할 수 없다는 경고를 표시할 수 있습니다.
4. 경고가 표시되면 `시스템 설정 > 개인정보 보호 및 보안`의 보안 영역에서 `확인 없이 열기`를 누르고 Mac 로그인 암호로 승인합니다. 출처가 이 공식 저장소인지 먼저 확인하세요.
5. 앱의 `시작 및 진단 > 손쉬운 사용 한 번에 설정`을 누릅니다. 열린 `시스템 설정 > 개인정보 보호 및 보안 > 손쉬운 사용`에서 `공지발송` 스위치를 켠 뒤 앱으로 돌아옵니다.
6. KakaoTalk을 실행해 로그인하고 채팅 탭이 정상적으로 열리는지 확인합니다. 이제 아래의 초기 데이터 설정을 진행합니다.

새 버전은 앱을 종료하고 새 ZIP의 `공지발송.app`을 기존 `/Applications/공지발송.app` 위에 교체해 설치합니다. 업데이트 후 실행 승인이나 손쉬운 사용 권한이 풀렸다면 위 4~5단계를 다시 수행합니다.

## 개발자 빌드

macOS Command Line Tools와 Swift 6 이상이 필요합니다.

```sh
swift run NoticeSender --self-test
./scripts/build-app.sh
./scripts/install-app.sh
```

첫 빌드에서는 XLSX 읽기용 `CoreXLSX 0.14.2`를 Swift Package Manager가 내려받습니다.
`install-app.sh`는 앱 전용 로컬 코드 서명 인증서를 최초 한 번 만들고 `/Applications/공지발송.app`에 설치합니다. 이후 빌드도 같은 인증서와 설치 경로를 사용하므로 손쉬운 사용 권한이 앱 업데이트마다 풀리지 않습니다.

## 처음 사용하는 순서

1. `시작 및 진단`에서 `2026 1학기.xlsx`를 가져옵니다.
   - 학생만 등록하려면 `학생 DB > XLSX/CSV 가져오기`를 사용합니다. 헤더는 이름·학교·학번·톡방 이름이 필수이고 `chat_id`는 선택입니다.
   - 현재 학생 DB는 `학생 DB > CSV 내보내기`로 저장할 수 있습니다. 내보낸 파일에는 학생 ID·이름·호칭·학교·2자리 학번·정확한 톡방 이름·`chat_id`·활성 상태가 포함되며, 같은 `XLSX/CSV 가져오기` 기능으로 다시 읽으면 학생 ID를 우선 기준으로 기존 정보를 갱신합니다.
   - `학생 DB > 운영 학번 설정`에서 현재 운영할 2자리 입학연도를 자유롭게 추가·삭제합니다. 카카오톡 DB 업데이트는 여기에 지정한 학번만 반영합니다.
   - `학생 DB > 카카오톡에서 DB 업데이트`를 누르면 내장 kmsg 엔진이 카카오톡의 `채팅` 탭을 직접 선택한 뒤 최근 채팅방을 최대 1,000개까지 읽습니다. 표준 학생방 제목에서 학교·학번·정확한 성명을 추출해 없는 학생은 추가하고, 기존 학생은 최신 톡방 이름과 `chat_id`를 갱신합니다. 카카오톡에 표시된 내부 띄어쓰기와 문장부호도 그대로 저장하며, 중복되거나 불명확한 후보는 자동 반영하지 않습니다.
2. 학생 DB의 중복 후보와 정확한 톡방 이름을 확인합니다.
   - 학생 상태는 `활성/비활성`으로 관리합니다. 더 이상 보관할 필요가 없는 학생은 표에서 선택한 뒤 `선택 학생 삭제`로 DB와 모든 반 명단에서 함께 삭제할 수 있으며, 기존 발송 기록은 유지됩니다.
   - 호칭은 이름에서 성과 알파벳을 제거하고, 마지막 글자에 받침이 있으면 `이`를 붙여 자동 생성합니다. 예: `김영준A → 영준이`, `구승모B → 승모`, `박하연 → 하연이`.
3. `학교 설정`에서 학교별 academy 문구를 입력합니다.
   - `반 관리`에서 새 반을 만들고 학생을 선택합니다. 저장된 반을 선택한 뒤 `이름 편집`으로 이름만 변경할 수 있으며 반 ID·학생 명단·기본 Preset은 유지됩니다. 반 파일 메뉴의 `전체 반 JSON 내보내기`는 모든 반, 연결된 학생 정보, 호칭 재정의와 기본 프리셋 참조를 한 파일에 저장합니다. 다른 Mac에서는 `반 JSON 가져오기`로 읽습니다.
   - 반 JSON을 가져오면 UUID가 같은 학생을 먼저 연결하고, 없으면 학교·학번·이름이 유일하게 같은 기존 학생을 재사용합니다. 기존 학생 정보는 덮어쓰지 않으며 파일에만 있는 학생은 새로 추가합니다.
4. `시작 및 진단 > 손쉬운 사용 한 번에 설정`을 누른 뒤 자동으로 열린 시스템 설정에서 `공지발송` 스위치만 켭니다. 앱이 권한 연결을 자동 재진단합니다.
   - 앱이 권한을 우회하거나 자동 승인할 수는 없습니다. macOS가 요구하는 스위치 조작은 최초 한 번 필요합니다.
5. 조교와 선생님은 지금 사용 중인 별도의 Google Sheet에 평소대로 동시에 기록합니다. 앱은 Google 계정이나 Sheet API에 연결하지 않습니다.
6. `수업 및 발송`에서 반·Preset·날짜를 선택합니다. 기본 Preset인 `직접입력`은 학생별 표의 `공지 멘트`를 그대로 사용하며, 다른 Preset은 전체 너비의 `진도, 숙제, 시험단원, 공지` 칸을 입력합니다.
7. Google Sheet에서 학생 결과 범위를 드래그해 `⌘C`로 복사합니다. 앱 학생 표에서도 마우스로 직사각형 셀 범위를 드래그 선택할 수 있으며 `⌘C/⌘V`로 Excel처럼 여러 행·열을 그대로 복사·붙여넣습니다. 셀을 더블클릭하면 한 칸을 직접 수정할 수 있습니다. 기존 `선택 칸부터 범위 붙여넣기` 버튼도 보조 방식으로 사용할 수 있습니다.
   - 표 위의 `선택 시작: 학생 · 열` 표시가 실제 붙여넣기 시작 위치입니다. 클릭하거나 드래그하면 즉시 갱신됩니다.
8. 총개수를 기준으로 계산된 학생별 실제 공지 멘트를 확인하고 `공지 바로 발송`을 누릅니다. 앱이 발송 목록 생성, 검증, 설정된 첨부폴더 검색을 한 번에 수행한 뒤 실제 발송을 시작합니다.
   - `직접입력` 실제 발송에서는 시스템이 각 학생의 호칭이 그 학생의 최종 공지 문구에 포함됐는지 정확하게 검사합니다. 호칭이 빠진 학생이 있을 때만 해당 학생 목록과 함께 경고가 뜹니다. `돌아가서 직접 확인`은 아무것도 보내지 않고 화면으로 돌아가며, `무시하고 직접 보내기`는 사용자가 누른 경우에만 계속합니다. 드라이런, 다른 Preset, 모든 학생의 호칭이 정상 포함된 경우에는 이 경고가 뜨지 않습니다.
9. 처음 사용하는 환경에서는 화면 아래 고급 발송 영역의 `드라이런`으로 먼저 확인하세요. 드라이런은 학생별 카카오톡 방을 검색하고 띄어쓰기까지 정확한 방 제목인지 검증하지만 메시지 입력, Enter, 첨부파일 전송은 하지 않습니다. 완료 후 `최근 작업 결과 > 상세 확인`에서 학생별 성공·실패를 다시 확인할 수 있으며, 실제 발송 뒤에도 같은 방식으로 재확인할 수 있습니다.

`수업 및 발송`은 교사 입력과 Google Sheet 학생 결과 입력, 미리보기, 첨부, 발송을 위에서 아래로 배치한 하나의 화면입니다. 기본 `직접입력` Preset에서는 학생별 표의 마지막 `공지 멘트` 열에 각 문구를 입력합니다. 첫 문자와 마지막 문자가 ASCII 큰따옴표(`"`)이면 그 한 쌍만 제거하고, 내부 공백과 줄바꿈을 포함한 나머지 문구는 그대로 발송합니다. 다른 Preset에서는 진도·숙제·시험단원·공지 입력칸과 학생별 성적·코멘트를 조합합니다. 반 명단은 `반 관리`에서 학생별 체크박스로 여러 명을 추가하거나 각 행의 휴지통 버튼으로 삭제합니다. 현재 검색 결과는 `전체 선택`으로 한 번에 고르고 `선택 해제`할 수 있습니다. 새 반을 만들 때 학교와 학번을 먼저 선택하면 학생 DB에서 둘 다 일치하는 활성 학생만 표시되며, 이 목록도 복수 선택과 전체 선택을 지원합니다. 왼쪽 목록에서는 선택한 반 또는 모든 반을 확인 후 삭제할 수 있으며 학생 DB와 저장된 수업 기록은 유지됩니다.

다른 탭으로 이동해도 `수업 및 발송` 화면의 수업 내용, 학생별 셀, 선택 범위, 미리보기와 검토 상태는 유지됩니다.

## 데이터 파일과 개인정보

- 학생 CSV는 학생 ID·이름·호칭·학교·학번·톡방 이름·`chat_id`·활성 상태를 담습니다. `학생 DB > CSV 내보내기`로 저장하고 `XLSX/CSV 가져오기`로 복원합니다.
- 반 JSON은 반 구성과 연결 학생 정보 및 기본 프리셋 참조를 함께 담아 다른 Mac에서도 명단 관계를 복원합니다.
- 전체 JSON 백업은 학생, 반, Preset, 설정과 로그를 포함하는 앱 전체 복구용입니다. `학생 DB > 백업/복원`에서 사용합니다.
- 학생 CSV, 반 JSON, 전체 백업에는 개인정보가 있으므로 공개 GitHub Release나 공개 저장소에 올리지 마세요. 권한이 제한된 저장소로 전달하고 사용 후 안전하게 보관합니다.

## 공통 메시지와 첨부파일

- `수업 및 발송` 화면 아래에서 반 전체에 동일한 메시지를 최대 5개까지 작성할 수 있습니다. 각 메시지는 합쳐지지 않고 순서대로 개별 전송됩니다.
- 첨부파일은 루트 폴더 주소 하나만 지정합니다. 앱이 모든 하위 폴더를 재귀 검색합니다.
- 파일명에 학생의 학교, 학번(`25` 또는 `2025`), 정확한 성명이 모두 포함된 일반 파일을 전부 연결합니다. 호칭으로는 매칭하지 않습니다.
- 숨김 파일, 폴더, 앱 패키지, 심볼릭 링크는 첨부 대상에서 제외됩니다.
- 메시지와 해당 학생의 모든 파일은 같은 검증된 채팅방에서 연속 처리됩니다. 파일별 `열기`/`Finder에서 보기` 동작과 업로드 완료를 확인한 뒤에만 채팅방을 닫으며, 시간 초과·중지·알림 발생 시에는 업로드를 방해하지 않도록 해당 방을 열어둔 채 전체 작업을 중지합니다.
- 실제 전송 전 학생별 메시지 개수와 첨부파일 목록을 반드시 검토하고 드라이런을 먼저 실행하세요.

## 수업 공지 Preset과 값 붙여넣기

직접 입력과 원본 `2026 1학기.xlsx`의 공지 멘트 수식을 기준으로 다음 6개 유형을 제공합니다.

1. 직접입력(기본): 학생별 `공지 멘트`를 그대로 사용하고, 양끝의 큰따옴표 한 쌍만 제거
2. 첫 수업
3. 시험만 있는 수업: 숙제검사 관련 문구는 `오늘은 진도상 숙제검사를 생략했습니다.`로 표시
4. 숙제만 있는 수업: 테스트 점수 대신 시험범위 문구 표시
5. 숙제와 시험 모두 있는 수업
6. 모의고사: Preset 편집기에서 1~3개 설정

기존 Google Sheet는 그대로 사용합니다. `수업 및 발송`의 로컬 표는 학생을 성명 오름차순으로 준비합니다. Google Sheet에서 드래그해 복사한 직사각형 범위를 선택한 시작 칸부터 그대로 붙여넣을 수 있습니다. A:J 전체 구조를 붙여넣으면 F/G의 숙제·테스트 총개수도 함께 가져오고, 학생 점수를 각각의 총개수로 나눈 비율을 공지에 반영합니다.

입력 실수는 상단 `입력 뒤로가기` 버튼 또는 `⌘Z`로 되돌립니다. 학생 표의 단일 셀 편집, 다중 셀 붙여넣기, 숙제·테스트 총개수 변경과 선생님 입력 내용을 최대 100단계까지 기록합니다.

학생 표에서 범위를 드래그한 뒤 Delete 또는 Backspace를 누르면 선택한 입력 셀을 한 번에 비웁니다. `⌘X`는 선택 범위를 복사한 뒤 삭제하고, 삭제·잘라내기 작업 전체는 `⌘Z` 한 번으로 복구됩니다. 번호·성명·호칭 같은 읽기 전용 셀은 범위에 포함되어도 삭제되지 않습니다. 개별 셀은 더블클릭하거나 선택 후 바로 타이핑해 수정하고 Return 또는 다른 셀 클릭으로 확정합니다.

## 안전 제한

- 실제 전송은 KakaoTalk 접근성 트리가 정확한 방 제목과 단일 입력창을 제공할 때만 허용됩니다.
- 안전형 kmsg 엔진은 이미 열려 있는 비슷한 제목의 방을 재사용하지 않고 매번 검색 결과를 확인합니다. 띄어쓰기·문장부호·대소문자를 포함한 방 제목이 정확히 일치하는 결과가 없거나 두 개 이상이면 방을 열거나 Enter를 누르지 않고 즉시 중지합니다.
- 검색창·검색 결과·채팅방·입력창은 AX 역할, 식별자, 설명, 정확한 제목과 부모 창 관계로만 찾습니다. 검색 결과 선택과 Enter는 카카오톡 프로세스 ID로 직접 전달하며 화면 좌표, 창 위치·크기, 현재 최상단 앱에 의존하지 않습니다.
- `chat_id`는 DB 동기화에서 같은 제목의 방을 구분하고 최신 방을 선택하는 식별자로 보관합니다. 발송 시에는 저장된 방 이름을 다시 정확히 검색해 결과가 하나인지 검증하므로, 같은 제목의 방이 두 개 이상 노출되면 안전하게 차단됩니다. 후보 DB 생성 시 마지막 메시지가 남은 방을 우선하고, 그중 카카오톡 최근 목록 최상단의 방을 선택합니다. kmsg가 메시지 시각을 제공하지 않으므로 최신성은 목록 순서로 판정합니다.
- 입력창을 찾지 못했을 때 현재 포커스 위치에 강제로 타이핑하는 kmsg 원본의 fallback은 비활성화되어 있습니다.
- 카카오 서버의 최종 수신 여부까지 보장하지 않으며 앱은 “정확한 방 확인 후 전송 입력 완료”까지만 기록합니다.
- 기록에는 공지 본문이 아닌 SHA-256 해시만 저장됩니다.
- 좌표 기반 클릭·창 배치, 이미지/OCR 추측, 공식 Kakao API 우회는 사용하지 않습니다.

## 문제 해결

- 앱이 열리지 않음: 앱을 한 번 실행한 직후 `시스템 설정 > 개인정보 보호 및 보안 > 확인 없이 열기`를 사용합니다.
- 손쉬운 사용 권한이 있는데 진단 실패: 손쉬운 사용 목록에서 기존 `공지발송`을 제거하고 `/Applications/공지발송.app`을 다시 추가한 뒤 앱과 KakaoTalk을 재시작합니다.
- 채팅방을 찾지 못함: 학생 DB의 `정확한 톡방 이름`이 KakaoTalk 화면의 띄어쓰기·문장부호·대소문자와 완전히 같은지 확인합니다.
- 일부 학생만 발송: 학생별 표의 번호 옆 체크박스를 해제하거나 `전체 선택/전체 해제`를 사용합니다.
- CSV 한글 깨짐: 앱은 UTF-8 BOM으로 내보냅니다. 외부에서 만든 파일은 UTF-8 또는 EUC-KR CSV/TSV로 저장합니다.
- 반 JSON 가져오기에서 명단 제외 발생: 같은 학교·학번·이름의 중복 학생을 학생 DB에서 정리한 뒤 다시 가져옵니다.
- 실제 발송 전에는 항상 드라이런으로 정확한 방 제목과 입력창을 확인하고, 최근 작업 결과의 상세 내역을 검토합니다.
